# Internationalization (i18n) Guide

The personal site is fully bilingual, supporting **English (`en`)** as the default language and **French (`fr`)**.

---

## 1. Directory Structure

Translations are stored in `apps/web/locales/`:

```text
apps/web/locales/
├── en/
│   ├── 404.json
│   ├── about.json
│   ├── blog.json
│   ├── climbing.json
│   ├── common.json        # Shared navigation, labels, buttons, dialogs
│   ├── contact.json
│   ├── index.json
│   ├── navigation.json
│   ├── posts.json
│   └── projects.json
└── fr/
    ├── 404.json
    ├── about.json
    ├── ... (mirrors en/)
```

---

## 2. Rules & Best Practices

1. **Dual Translation Requirement**:
   Whenever adding, modifying, or removing any user-facing string:
   - Always update **both** `locales/en/<namespace>.json` AND `locales/fr/<namespace>.json`.
   - Never leave French strings untranslated or missing keys.

2. **Namespace Selection**:
   - Page-specific strings belong to their page namespace (e.g., `about.json`, `projects.json`, `index.json`).
   - Shared text (navigation buttons, footer text, toast alerts, common labels like "Read More" or "Close") belongs to `common.json`.

3. **Querying Translations in Gatsby Pages**:
   In page files, Gatsby queries locale resources through the `locales` GraphQL query:

   ```tsx
   export const query = graphql`
     query IndexQuery($language: String!) {
       locales: allLocale(filter: { language: { eq: $language } }) {
         edges {
           node {
             ns
             data
             language
           }
         }
       }
       # ... other queries
     }
   `;
   ```

4. **Using the Translation Hook in Components**:
   Import `useTranslation` from `gatsby-plugin-react-i18next`:

   ```tsx
   import { useTranslation } from "gatsby-plugin-react-i18next";

   const MyComponent = () => {
     const { t } = useTranslation("common"); // Or specify namespace
     return <button type="button">{t("buttons.submit")}</button>;
   };
   ```

5. **Internal Navigation**:
   Use `Link` from `gatsby-plugin-react-i18next` instead of standard `gatsby` or Reach Router to preserve the active language prefix (`/` vs `/fr/`):

   ```tsx
   import { Link } from "gatsby-plugin-react-i18next";

   <Link to="/about">{t("nav.about")}</Link>
   ```
